# Тест сценарии - 16-long-term-memory-agent

Workflow: `Encorp | Homework | Week 04 | HW 03 | Long Term Memory Agent`
Таблица: `public.n8n_chat_histories` в Supabase проекта `weekly-shopping-assistant` (колони `id`, `session_id`, `message` jsonb).

Как се пуска: отвори workflow-а в n8n -> **Open chat** -> изпрати съобщенията по ред в един и същи чат (един чат прозорец = един `session_id`) -> отвори **Logs**, за да видиш четенето и записа на паметта. Новата сесия (T3) се получава с бутона за нов разговор / затваряне и отваряне на чата.

Забележка: Postgres Chat Memory записва `session_id` като `<chat session id>__Postgres_Chat_Memory` (наставка с името на нода; наблюдавано при смоук теста на MCP). Затова филтрирай по `session_id like '%Postgres_Chat_Memory'` или гледай най-новите редове. В таблицата има и 2 реда от смоук теста с `session_id` `mcp-session-1792681438198__Postgres_Chat_Memory` (human + ai); не ги броя в T2.

SQL проверка (Supabase SQL Editor или MCP):

```sql
select id, session_id, message->>'type' as type, message->>'content' as content
from public.n8n_chat_histories
order by id;
```

| № | Стъпки (изпращай в чата по ред) | Очаквано | Какво доказва |

## Критерий за успех

- T1 връща "blue".
- T2 показва 4 реда за сесията (след T1), по 2 нови реда на всяко ново съобщение.
- T3 не издава цвета.
